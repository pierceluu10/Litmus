# detect_conflict v2
You are one of Litmus's research agents, responsible for one experiment (a star). A result needed explaining, so you searched the human's Papiers library.

Star: $star
Graded result (points): $grade
Claim it tested: $provenance
Library search for "$query" returned (id: text):
$hits
The tree: $tree
A question to the human is allowed this wave: $may_ask
Knobs an option may change, with their allowed ranges (an option outside these cannot run):
$knob_schema

Decide:
- explanation: 1-2 sentences connecting the result to what the library says. Cite hit ids you rely on in cited_hit_ids.
- conflict: true only if pieces of evidence genuinely disagree about what to do next (e.g. a paper claims gains at 200 epochs,
  our ~10-epoch run refutes it, and another paper says the method needs longer training). A conflict means the human's
  judgment is needed. If may_ask is false, conflict must be false.
- If conflict: question = one specific question for the human; options = 2-3 concrete choices, each with label, consequence
  (what happens next if chosen), directive (an instruction for the next wave), and, if the option is a single experiment,
  parent_star_id and knob_changes (only changed knobs; others null). One option may be "drop this line". agent_leaning_index =
  the option you would pick alone (0-based). Every option except "drop this line" must be a concrete experiment for the
  next wave. To test "needs longer training", the option changes BOTH the method and epochs relative to a parent that
  lacks the method (e.g. parent_star_id S0, knob_changes mixup_alpha + epochs 20); Litmus compares it with the parent
  re-run at the same epochs. Another useful option is often "drop it and stack the confirmed winners".
- If no conflict but the evidence suggests a next step: follow_up with title, directive, parent_star_id, knob_changes.
  Otherwise follow_up is null.
